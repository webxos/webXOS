9. INTEGRITY, HASH CHAINS & RECONSTRUCTION FOOTER


Every Cloudform file ends with an integrity footer that enables end-to-end
verification and progressive checkpointing. The footer contains at minimum:


  • Full-content SHA-256 (or stronger) of all data bytes following the
    magic header.

  • Optional progressive checkpoint hashes—one per major plane or logical
    slice—so that a receiver can verify each stage without waiting for the
    complete download.

  • Optional erasure-coding parity blocks (when ERASURE_HINTS flag is set)
    sized according to the expected packet-loss characteristics of the
    target constellation link.

  • Optional cryptographic signature (when SIGNED flag is set) over the
    content hash, produced by a constellation-root or ground-station key.

  • A fixed end-of-artifact marker (ASCII “CFB_END\0”).


Because the progressive hash chain is itself part of the transmitted stream,
a receiver can abort early upon detecting corruption and request only the
missing planes, dramatically improving effective goodput on lossy optical
or RF links.


Verification under Progressive Mode
-----------------------------------

Under progressive mode the receiver can verify each plane as it arrives and
abort or request selective retransmission upon hash failure. This early-abort
capability is particularly valuable on optical inter-satellite or
space-to-ground links where residual bit-error rates, although low, can still
corrupt large transfers if left unchecked until the end.


Loss Resilience
---------------

Optional erasure-coding parity blocks may be appended when the ERASURE_HINTS
flag is set; their size and placement are recorded in the header so that a
receiver can recover from a bounded number of lost packets without
retransmission. When the SIGNED flag is set, a constellation-root or
ground-station signature over the content hash is included, enabling
provenance verification in multi-party orbital networks.


Security Considerations
-----------------------

Security considerations include the strength of the chosen hash and signature
algorithms under the radiation and side-channel environment of LEO, as well
as the implications of allowing partial artifacts to drive autonomous
decisions. These topics warrant dedicated follow-on study. Implementations
should treat the progressive approximation as a lower-confidence input until
the final content hash and optional signature have been verified.
