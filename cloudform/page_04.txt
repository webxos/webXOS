3. Formal Specification of the Cloudform Binary Format


A Cloudform file is a contiguous byte stream consisting of four ordered regions: (1) a fixed 16-byte
magic-and-version header, (2) a length-prefixed binary header chunk, (3) one or more 16-byte-aligned data
buffers that may themselves be decomposed into progressive bit-planes, and (4) an integrity footer.


3.1 Magic Header


Bytes 0–3 contain the ASCII signature “CFB1”. Bytes 4–5 encode a little-endian version number. Bytes 6–7
encode a bit field whose low-order bits declare progressive mode, GPU alignment guarantee, presence of
signatures, primary 1-bit quantization, and erasure-coding hints. Bytes 8–15 contain the total file length as a
little-endian uint64, enabling a receiver to allocate or reject the artifact before any further parsing.


3.2 Header Chunk


The header chunk begins with a uint32 length followed by a compact key-value binary encoding of artifact
identity, content hash, megalith type, quantization and packing mode, alignment preference, progressive
streaming map (offsets and sizes of each plane), optional constellation routing metadata, GPU dispatch tags,
and an LLM seed string. The seed string is deliberately retained so that an upstream or downstream language
model can regenerate, continue, or validate the artifact without external documentation.


3.3 Progressive Bit-Plane Data Region


When progressive mode is active, each quantizable buffer is emitted as an ordered sequence of bit-planes.
Plane 0 contains the most significant bit of every element (or an equivalent significance ordering for sparse or
graph structures). Subsequent planes add successive lower-significance bits. Each plane is preceded by a
mini-header that records the plane index, parent buffer identifier, byte length, and a running cryptographic hash
of all preceding planes of that buffer. This hash chain provides immediate detection of missing or corrupted
planes and enables selective retransmission requests.
