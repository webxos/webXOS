6. CLOUDFORM HEADER CHUNK


Immediately following the 16-byte magic header is a length-prefixed binary
header chunk. The first 4 bytes are a uint32 little-endian length of the
remaining header payload. The payload itself is a compact, key-value binary
structure that is intentionally model-readable (an LLM can emit or parse it).


Required and recommended fields include:


  • artifact_id          unique identifier (UUID or content-addressed string)

  • content_hash         SHA-256 (or stronger) of the entire data section

  • megalith_type        knowledge_graph | weight_tensor_set |
                         sensor_archive | hybrid | custom

  • quantization         1bit | 4bit | 8bit | fp16 | fp32 | mixed

  • packing              bitplane | sparse | dense | hybrid

  • alignment            preferred alignment in bytes (16 / 32 / 64 / 128)

  • mode                 progressive | atomic

  • gpu_dispatch_tags    optional list of preferred accelerator targets

  • streaming_map        offsets and sizes of progressive planes / slices

  • route                source (orbital / earth), destination, priority class

  • llm_seed             short natural-language description enabling
                         regeneration or continuation

  • constellation_meta   optional orbital plane, preferred ground stations,
                         latency class


The header is deliberately kept compact so that edge LLMs and radiation-
hardened processors can parse it with minimal memory. Vendor extension
blocks may follow the standard fields; they must be length-prefixed and
ignorable by implementations that do not understand them.


--------------------------------------------------------------------------------
7. BINARY DATA CHUNKS & ALIGNMENT
--------------------------------------------------------------------------------

One or more tightly packed buffers follow the header. Each buffer is preceded
by a mini-header containing type, quantization level, sparsity map offset
(if any), and length. All buffers are required to be 16-byte aligned (higher
powers of two are preferred when the GPU_ALIGNED flag is set).


Supported buffer types include:

  • tensors (dense or sparse)
  • knowledge-graph adjacency / edge lists
  • key-value stores
  • raw opaque blobs


Sparse and 1-bit modes store a compact index plus bit-packed planes so that
memory footprint collapses dramatically while still allowing direct mapping
into GPU memory (CUDA, Vulkan, Metal, or rad-hard TPU equivalents).


Because the layout is sequential and deterministic, a runtime can mmap the
file (or a progressive window) and obtain usable pointers with essentially
zero transformation cost. Prefetch and streaming maps living in the main
header allow a receiver to pull only the next needed slice under tight
downlink windows.


Implementation Requirements for Buffers
---------------------------------------
  • 16-byte (or higher) aligned packing for dense tensors.
  • Deterministic emission order so that identical source data always
    produces identical binary (enables differential and content-addressed
    caching).
  • Optional transpose flags for GPU-preferred layout.
  • Mini-header before every buffer so that a partial stream can still
    identify what has arrived.
